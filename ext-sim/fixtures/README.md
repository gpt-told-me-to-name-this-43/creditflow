# Формат фикстур ext-sim

Ответы `ext-sim` детерминированы и берутся из этого каталога (design.md §3.4). Все фикстуры читаются и валидируются при старте сервиса: ошибка в любом файле не даёт `ext-sim` запуститься, а `make test` в `ext-sim` её показывает.

Формат ниже — контракт: по нему #6 готовит демо-компании C1–C7 и T1, изменения формата идут через PR с правкой этого файла и тестов `ext-sim`. Сейчас в каталоге только образец — ООО «Образец» (`0099000014`).

## Каталог компании

```text
fixtures/
└── <inn>/              # ИНН: 10 цифр — ЮЛ, 12 — ИП
    ├── egrul.json      # для ЮЛ — запись ЕГРЮЛ
    ├── egrip.json      # для ИП — запись ЕГРИП (ровно один из двух файлов)
    ├── fns.json        # необязательно; нет файла → 404
    ├── bki.json        # необязательно; нет файла → 404
    ├── statement.json  # необязательно; нет файла → 404
    └── meta.json       # необязательно: режим сбоя
```

ИНН в реестровой записи должен совпадать с именем каталога. Неизвестный ИНН — `404` на всех endpoint-ах.

## Файлы

Имена полей и типы совпадают с ответами в `docs/openapi-ext-sim.json`. Деньги — строки с двумя знаками после точки (`"45000.00"`), числа с плавающей точкой не допускаются. Лишние поля запрещены.

| Файл | Содержимое | Ответ |
| --- | --- | --- |
| `egrul.json` | `inn`, `ogrn` (13 цифр), `name`, `status`, `registered_at` (`YYYY-MM-DD`), `okved_main`, `director{full_name, inn}` | `GET /egrul/v1/companies/{inn}` — файл как есть |
| `egrip.json` | `inn`, `ogrnip` (15 цифр), `full_name`, `status`, `registered_at`, `okved_main` | `GET /egrip/v1/entrepreneurs/{inn}` — файл как есть |
| `fns.json` | `bankruptcy` (bool), `active_account_blocks` (≥ 0), `checked_at` (ISO 8601 с зоной) | `GET /fns/v1/companies/{inn}` — файл как есть |
| `bki.json` | `summary_status`, `monthly_payments_total_rub`, `obligations[]{creditor_name, monthly_payment_rub, outstanding_rub}` | `POST /bki/v1/reports` — файл и `report_id` |
| `statement.json` | `account_masked`, `transactions[]` | `GET /bank/v1/statements` — `inn`, `account_masked`, `from`, `to` и операции периода |
| `meta.json` | `fail_mode` | — |

- `status`: `ACTIVE` / `LIQUIDATING` / `LIQUIDATED`.
- `summary_status`: `CLEAN` / `UNKNOWN` / `MINOR` / `SERIOUS`.
- `report_id` не хранится: он вычисляется детерминированно из ИНН и `consent_id` (UUID v5).

### Операция выписки

```json
{
  "external_id": "0099000014-000003",
  "booked_at": "2026-09-05",
  "direction": "IN",
  "amount_rub": "350000.00",
  "counterparty": {"inn": "0099000021", "name": "ООО «Покупатель Образца»", "is_bank": false},
  "purpose": "Оплата по счёту № 17 от 01.09.2026"
}
```

- `external_id` — уникален в пределах компании и стабилен между перегенерациями: по нему `api` делает upsert в `account_transactions` (design.md §3.7).
- `direction` — `IN` или `OUT`; `amount_rub` — всегда положительная сумма.
- `counterparty.inn` может быть `null` (например, выплаты сотрудникам).
- Период запроса `from`/`to` включает обе границы; операции отдаются в порядке файла.

## Режимы сбоя

`meta.json`:

```json
{"fail_mode": "bki_timeout"}
```

Формат — `<источник>_<режим>`:

- источник: `egrul`, `egrip`, `fns`, `bki`, `bank`;
- режим: `timeout` (соединение держится 30 с, затем `504`), `500`, `503`.

Сбой срабатывает только на endpoint-е указанного источника; остальные отвечают данными. Кроме фикстуры, сбой можно вызвать на любом ИНН заголовками запроса:

| Заголовок | Значение |
| --- | --- |
| `X-Sim-Fail` | `timeout`, `500` или `503` |
| `X-Sim-Latency-Ms` | задержка перед ответом, 0–30000 мс |

## Ошибки

Все ошибки `ext-sim` отдаёт в одном формате:

```json
{"error": {"code": "NOT_FOUND", "message": "Нет данных по ИНН"}}
```

`details` — необязательный массив `{loc, msg, type}`, есть только у `422 VALIDATION_ERROR`.

| HTTP | `code` | Когда |
| --- | --- | --- |
| 403 | `CONSENT_REQUIRED` | `POST /bki/v1/reports` без `consent_id` |
| 404 | `NOT_FOUND` | нет каталога ИНН или файла источника |
| 422 | `VALIDATION_ERROR` | некорректный ИНН, дата, заголовок `X-Sim-*` |
| 422 | `INVALID_PERIOD` | `from` позже `to` |
| 500 | `SIMULATED_ERROR` | режим сбоя `500` |
| 503 | `SIMULATED_UNAVAILABLE` | режим сбоя `503` |
| 504 | `SIMULATED_TIMEOUT` | режим сбоя `timeout` |

## Синтетические ИНН и ОГРН

ИНН и ОГРН должны проходить контрольную сумму и не совпадать с реальными. В образце используется код региона `00` — его нет ни в одном настоящем ИНН или ОГРН, поэтому совпадение с реальной организацией исключено:

| Поле | Значение | Устройство |
| --- | --- | --- |
| ИНН ЮЛ | `0099000014` | регион `00`, инспекция `99`, номер `00001`, контрольная цифра `4` |
| ОГРН | `1210099000011` | признак `1`, год `21`, регион `00`, остаток от деления на 11 → `1` |
| ИНН руководителя | `009900000120` | регион `00`, две контрольные цифры `20` |

Контрольные цифры: для 10-значного ИНН — Σ(цифра·вес) mod 11 mod 10 с весами `2 4 10 3 5 9 4 6 8`; для 12-значного — две цифры с весами `7 2 4 10 3 5 9 4 6 8` и `3 7 2 4 10 3 5 9 4 6 8`; для ОГРН — первые 12 цифр mod 11 mod 10, для ОГРНИП — первые 14 цифр mod 13 mod 10.
